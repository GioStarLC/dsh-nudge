# dsh-nudge

一个 DSH Web 插件：在对话上方浮一个可拖动的小窗，选好「口径」点一下按钮——光标在输入框时把口径追加进草稿，否则向 agent 询问状态，回答直接写进对话里。

## 它做什么

- **触发**：悬浮窗里的主按钮，手动点击，不做定时、不做轮询。按钮文案随光标位置切换：
  - 光标不在输入框：显示「询问状态」，把选中的口径发给 agent，回答落回对话。
  - 光标在对话输入框：显示「写入输入框」，不发送，把选中的口径追加到草稿末尾；草稿已有内容时先补一个换行再写，光标停在写入文本之后。此时「方式」不可用（写入不涉及投递）。
- **急速模式（可在设置页开关，也可点「快捷输入」行尾的闪电按钮）**：开启后隐藏底部主按钮，改为**双击口径直接执行**——双击等同于「选中该口径 + 点一次主按钮」，所以光标在输入框时是写入、否则是发送。
- **口径（可选项，平铺）**：窗口里把口径平铺成一排按钮，点哪个就用哪个：

  | 默认口径 | 发给 agent 的话 |
  |---|---|
  | 简述 | 简述一下：目标、已完成、下一步、是否需要我。 |
  | 快一点 | 快一点，别先急着测试，先开发完。 |
  | 四行 | 按固定四行汇报当前状态：Goal / Done / Next / Needs you；无内容写「无」；不复述工具调用、不贴日志。 |

  口径可以**编辑、新增、删除、恢复默认**：设置页里的「状态询问」一节。
- **回答**：回答落在对话里（和普通回复一样）。插件不解析、不展示内容，只判断「回答到了没有」来更新状态图标。
- **方式**：走输入框同一条投递通道，和「方式」二字同排的一行小分段开关。
  - **直接打断**（默认，映射为 `steer`）：立即插入当前任务，在最近一个 step 边界生效；
  - **排队**（映射为 `queue`）：排到当前任务之后，作为下一轮发出。
- **边界**：没有打开的会话 / 会话已结束或归档 / 投递失败都会在窗口里给出明确提示；agent 正在等待用户回答时拒绝发起并提示「agent 正在等待你的回答」。
- **防堆积**：等待回答期间按钮禁用，不会向同一会话堆第二条询问。
- **批注（「批注」行尾的快速批注按钮）**：打开后——
  - 在对话里选中文字，**鼠标位置旁（右边放不下翻到左边、下边放不下翻到上边）弹出批注卡片**（不移动 nudge 窗口）；卡片贴着指针显示，键盘选区则退回按原文框定位。
  - 卡片是一张纯输入卡：**不重复显示原文**（原文由标记高亮体现），打开即把光标放进输入框，选中文字后可以直接打字；输入框下是单行 `👍 同意 / 👎 不同意` 与 `复制 / 取消 / 添加批注`，右上角 `×`。卡片默认压暗，指针移入或聚焦后提亮。
  - 「复制」把引用放进剪贴板，按钮就地变成「已复制」（失败则「复制失败」），不关闭卡片；点卡片外、`×`、按 Esc 或滚动时卡片关闭。
  - 添加批注后卡片关闭、原文标黄；nudge 窗口里的「批注」模块就是批注仓库：计数 + 列表 + 「写入输入框 / 发送」。点仓库条目可就地编辑/删除。
  - 被批注的原文用黄色高亮标在对话里（基于 flow item 锚点，滚动/重渲染后自动重绘）。
  - 批注按会话持久化在浏览器本地，刷新或切回会话仍在；切换会话会自动加载对应会话的批注。


## 界面

- 窗口标题就叫 `dsh-nudge`；两个可折叠模块：「批注」（快速批注开启时出现，是批注仓库：列表 + 写入/发送）和「快捷输入」（口径平铺、主按钮）。每行标题右侧是该行自己的控件；划线时窗口本身不展开、不移动，批注卡片贴着鼠标显示。
- 标题栏从左到右：状态图标 + 名称 + 设置齿轮 + 收起。
- **行内控件**：`批注` 行尾是快速批注开关（引号图标，开态淡蓝底）；`快捷输入` 行尾是方式切换（`直接打断` 用跳进图标、`排队` 用双箭头）与急速开关（闪电图标，开态淡蓝底）。都是纯图标按钮，悬停给出简短说明，点击后窗口里出现一行中文提示当前切到了什么（约 1.6s 自动消失），例如 `方式：排队`、`急速模式：开`、`快速批注：开`。
- **设置入口**：标题栏右侧的齿轮按钮直接打开 DSH 设置面板并定位到「状态询问」；设置面板不可用时在窗口内提示从侧边栏进入。
- 不再显示会话名、上次播报时间、引导语；状态只在标题栏的手势图标上体现（灰=未询问、黄=等待中并伴随轻点动画、绿=已返回、红=失败），出错时在按钮上方显示提示条。
- **收起就地变小**：点击标题栏右侧的收起按钮后，卡片在原位置缩成一个小胶囊（同一个左上角锚点），展开也在原地；**胶囊本身也能拖动**，位置照样记忆；胶囊同样显示状态图标与未读提示点。标题栏可拖动，但单击标题栏不再收起。
- 视觉：16px 圆角卡片、柔和投影、深浅主题统一使用 DeepSeek 蓝强调色（不再有黑/白反转）、胶囊口径按钮、蓝色淡底选中态、悬停/按下过渡；全部基于主题变量，日/夜自动适配。
- `shell.overlay` 浮层，`position: fixed`，不随对话滚动；标题栏可拖动，位置记在 `localStorage`。
- 窄屏（< 720px）默认收起；首次默认停靠右上、避开输入区，右侧栏（better-sidebar）展开时会向左避开它的宽度。

## 配置

零配置即可用。所有可调项都在界面上，存在浏览器本地：

- 窗口里「口径」平铺按钮：选询问文案（默认第一条「简述」）。
- 窗口里「方式」：一行小开关，直接打断（默认）/ 排队。
- 设置页「状态询问」：编辑名称与文案、新增、删除、恢复默认（最多 8 条）；正文输入框随内容自动增高（上限约 320px / 40vh，再长则框内滚动），设置弹窗也随之长高到内容高度（不超过窗口可用高度），不再把正文裁在固定框里。顶部有「急速模式」开关，勾选即时生效。
- `localStorage` 键：`dsh-nudge:presets`、`dsh-nudge:preset`、`dsh-nudge:delivery`、`dsh-nudge:turbo`（`'1'` 为开启）、`dsh-nudge:quick`（快速批注开关）、`dsh-nudge:notes`（按会话的批注与锚点）；非法值会回退默认并 `console.warn`，不阻塞载入。
- 默认值只有一处：`client.js` 的 `DEFAULT_DELIVERY` 与 `BUILTIN_PRESETS`/`DEFAULT_PRESET`。

## 结构

| 路径 | 作用 |
|---|---|
| `index.js` | Host 半边：只占一个 Loader 行（让浏览器半进入 boot graph），无配置、无依赖 |
| `client.js` | 浏览器半边：悬浮窗、口径平铺与设置页、投递、状态判定 |
| `cordis.patch.yml` | bundle 的插件行 |
| `locale/*.json` | Plugin Manager 显示用的标题与描述 |
| `scripts/check-host.mjs` | Host 行挂载检查 |
| `scripts/check-client.mjs` | 用 VM 装载真实 bundle，驱动投递、口径、窗口状态与事件判定 |
| `scripts/harness.mjs` | 共享的 VM 装载器与 JSX→HTML 序列化（check 与 preview 共用同一套桩，`boot()` 在此） |
| `scripts/preview.mjs` | 把真实 bundle 渲染成命名场景的截图（`preview-out/*.png`），改完 UI 直接看图，不用手搓临时 HTML |
| `.githooks/pre-commit` | 提交前跑 `npm run check`，红灯即阻止提交 |

## 验证

```bash
npm run check          # client + host 两半的检查（pre-commit 钩子会跑这条）
npm run preview:all    # 渲染全部命名场景 + 夜间样式到 preview-out/
npm run preview -- popup --dark   # 单个场景；--list 看全部场景名
```

`npm run check` 任一检查失败即以非零码退出；`.githooks/pre-commit` 已 `git config core.hooksPath` 接上（新克隆执行一次 `npm install` 会通过 `prepare` 自动接上）。`client.js` 改动前建议先 `npm run preview:all` 看图核对视觉，再跑 `npm run check` 确认行为。

界面行为（拖动、收起、窄屏、夜间样式）可由 `preview.mjs` 的场景渲染覆盖静态外观；真实交互（拖动、点击）仍需刷新页面后人工确认，插件不注册任何自己的页面根节点，卸载槽位即移除窗口。

## 已知边界

- **「已返回」的判定**：只看会话日志里的事件类型与 seq，不看回答内容。请求带着客户端生成的 `requestId` 投递，Host 把它记成 user message 的 `source.rpcId`；插件以此定位这次询问，并认为「消费该消息的 step 之后的第一条带文本 assistant 消息」就是回答。steer 在长任务中也能及时变成「已返回」，不必等整轮结束。
- **失败也算清楚**：该轮的 `turn/end` 若是 `blocked`（归档/被阻止）、`failed`、`aborted`，或以 `completed` 结束却没有文本回答，窗口显示失败原因，不假装「已返回」。
- **兜底**：拿不到会话事件窗口时（例如会话绑定不可用），退回 running 状态启发式（真→假 + 1.2s 静默 / 8s 未运行兜底）；此时「已返回」是近似，文案会说明未确认。
- **超时**：agent 仍在运行时持续等待；确认不到投递（15s）或空闲后仍无回答时才报失败。
- **对话切换**：窗口状态绑定点击时的会话；切换到别的会话会重置为「未询问」，不会把上一个会话的「已返回」带过去。
- **设置入口**：齿轮优先点击侧栏里原生的设置按钮（`button[aria-haspopup="dialog"]`，限定在 `[data-slot="sidebar.settings"]` 内）；该位置被账号菜单占用时（本机即如此）改走 shell 注册的 `settings.open` 命令打开同一面板，再点导航里的「状态询问」。不做全文档 `aria-haspopup="dialog"` 匹配——那会点到会话头部的「团队成员」弹窗。
- **设置弹窗高度**：shell 的设置面板原本固定为 `min(800px, 视口高度减边距)`。插件只在「状态询问」页挂载期间用 `body:has(.dsh-nudge-settings)` 覆写它的 `height/min-height/max-height`，让面板随该页内容长高；切到其他分区即恢复 shell 原样。DSH 改版设置外壳时，这条覆写需要重新核对。
- **写入输入框**：写入走会话输入浮层（`conversation.input.overlay`）拿到的 composer `inputActions.setDraft`，不是模拟键盘或改 DOM；草稿里已有的 `@` 引用会被重新解析。只有光标在输入框内（`[data-composer-input]` / Lexical 编辑器）才进入写入模式；输入框不可用时按钮仍按询问处理并在窗口里提示。
- **批注格式**：每条批注写成 Markdown 引用块（多行逐行加 `>`，空行写成单独的 `>`），有注时紧接一行 `我的回答：<注>`；多条之间空一行。`我的回答：` 是刻意保留的标记，否则紧跟引用块的普通行会被当成引用的延续。
- **批注选区**：输入框、设置弹层、本窗口内的选区都不引用。mouseup 后去抖 200ms 才出卡片（避开双击选词），卡片出现时**不抢焦点**，原生选区保持；只有点卡片输入框才聚焦，插件在聚焦/输入后恢复原生选区（`restoreCaptureSelection`），同时用 `::highlight(dsh-nudge-capture)` 画同色兜底高亮（复刻 Chromium 原生深蓝 `#3367d1` + 白字，逐像素实测一致；可用 CSS 变量 `--dsh-nudge-capture-bg` / `--dsh-nudge-capture-fg` 覆盖）。卡片跟随选区定位：默认贴在选区上方、底边锚定（输入框长高时向上生长），上方放不下才落到下方，左右夹在视口边距内；点外部、`×`、Esc、滚动、resize 都会关闭。锚点在点「添加批注」时才计算（避免每次 mouseup 遍历整条消息）。批注锚定对话 flow item（`data-chat-anchor-key`），按「引用文本 + 前后文」定位标黄；定位有歧义时宁可不画。批注存 `localStorage` 的 `dsh-nudge:notes`（按会话，最多 200 条 / 40 个会话）。
- **与 dsh-popup 并存**：desktop profile 里 `dsh-popup` 仍在启用，选中助手回复后它也会直接弹出自己的批注卡片（早期那个 32px 圆点气泡已经删掉，现在是 mouseup 后直接出卡）。两者同时开启时，同一个选区会叠出两张卡；要单独体验 nudge 的批注，先在插件管理里禁用 popup，或在标题栏关掉「快速批注」（默认关）。
- `steer` 在 agent 空闲时同样会开启一轮（这是 DSH 投递语义，插件不额外拦截）。
